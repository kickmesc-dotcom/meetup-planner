# Публичный API и вебхуки

Версия: **v1** (шаг 6.1, 04.11.2026). Контракт `/api/v1` и события вебхуков
меняются только с новой версией; внутренние ручки `/api/hr/...` — нет.

Зачем это существует: CRM, телефония и учётная система должны получать людей и
график, не имея пароля владельца и не читая базу. Ключ выписывается на
организацию, ограничен чтением и отзывается в один клик.

## Ключ

Ключ создаётся в кабинете: **Настройки → Интеграции → Ключи API**. Он
показывается **один раз**; в базе лежит только SHA-256 и префикс, поэтому
восстановить забытый ключ нельзя — можно только выпустить новый.

Передаётся заголовком:

```
X-Api-Key: stk_live_…
```

Ключ открывает данные **только своей организации**: организация берётся из
строки ключа, а не из параметров запроса. Подставить чужой id нечем.

| Право (scope) | Что открывает |
| --- | --- |
| `people.read` | подразделения и люди: имя, должность, плашка, подразделение |
| `schedule.read` | график смен за период |
| `menu.read` | меню смены |
| `contacts.read` | почта сотрудника (персональные данные, отдельное решение) |

По умолчанию ключ получает всё, кроме `contacts.read`. Неизвестное право —
ошибка `400 unknown_scope:…`, а не молча отброшенное.

Ключ считается использованным (`last_used_at`) не чаще раза в 5 минут — это
поле для человека, а не аудит.

## Ошибки

| Код | `detail` | Что значит |
| --- | --- | --- |
| 401 | `api_key_invalid` | ключа нет, он отозван или неверен |
| 403 | `scope_required:<scope>` | ключ живой, но права на ручку нет |
| 403 | `org_missing` / `org_inactive` | организация удалена или на паузе |
| 429 | `org_rate_limited:<секунды>` | лимит частоты тарифа, есть `Retry-After` |
| 400 | `range_invalid`, `range_too_long` | период графика перевёрнут или больше 92 дней |

Лимит частоты — по организации (тариф), а не по IP: за прокси интегратора
может стоять несколько сервисов, и все они один клиент.

## Ручки

### `GET /api/v1/me`

Проверка настройки: чья организация, чей ключ и что ему можно.

```json
{
  "org_id": 1,
  "org_slug": "salon-a",
  "org_name": "Салон А",
  "key_name": "CRM",
  "scopes": ["people.read", "schedule.read", "menu.read"]
}
```

### `GET /api/v1/departments?include_inactive=false`

```json
[{"id": 3, "name": "Бар", "slug": "bar", "emoji": "🍸", "is_active": true}]
```

### `GET /api/v1/employees?include_inactive=false&limit=100&offset=0`

`limit` ≤ 200. Порядок — по `id`, чтобы страницы не перескакивали.

```json
[{
  "id": 12,
  "name": "Анна Петрова",
  "position": "бармен",
  "badge": "Бармен",
  "department_id": 3,
  "is_active": true,
  "hired_at": "2026-02-01",
  "email": null
}]
```

`email` приходит только ключу с `contacts.read`; иначе `null`, а не «поле
исчезло» — схема ответа одна для всех.

### `GET /api/v1/shifts?from=2026-11-01&to=2026-11-07`

Период обязателен, не больше 92 дней. Пустая ячейка графика **отсутствует** в
ответе, а не приходит днём с `null`: «нет смены» и «смена без часов» — разные
вещи.

```json
[{
  "id": 501,
  "employee_id": 12,
  "employee_name": "Анна Петрова",
  "day": "2026-11-05",
  "status": "planned",
  "starts_at": "10:00",
  "ends_at": "18:00"
}]
```

### `GET /api/v1/menu`

```json
[{"id": 7, "category": "Напитки", "name": "Апероль", "price_rub": 590, "is_available": true}]
```

## Вебхуки

Создаются там же: **Настройки → Интеграции → Вебхуки**. Секрет подписи
показывается один раз.

События:

| Событие | Когда |
| --- | --- |
| `employee.created` | сотрудник заведён в организации |
| `employee.updated` | изменены имя, должность, плашка или роль; возврат из корзины |
| `employee.deactivated` | сотрудник уволен |

Доставка:

```
POST https://crm.example.com/hooks/semitask
Content-Type: application/json
X-SemiTask-Event: employee.created
X-SemiTask-Delivery: 918
X-SemiTask-Signature: sha256=…
```

Тело:

```json
{
  "event": "employee.created",
  "org_id": 1,
  "sent_at": "2026-11-04T10:15:00+00:00",
  "data": {"employee_id": 12, "name": "Анна Петрова", "position": "бармен", "department_id": 3}
}
```

Подпись — HMAC-SHA256 от **сырого тела** запроса, ключ — секрет вебхука:

```python
import hmac, hashlib

def valid(secret: str, body: bytes, header: str) -> bool:
    expected = "sha256=" + hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header)
```

```js
const crypto = require("crypto");
const expected = "sha256=" + crypto.createHmac("sha256", secret).update(rawBody).digest("hex");
crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(header));
```

Правила повторов:

- успех — любой `2xx`; всё остальное (включая `3xx`, редиректы не
  выполняются) — неудача;
- до 5 попыток: через 1 мин, 5 мин, 30 мин, 2 ч, 6 ч;
- тело повтора — **тот же снимок**, что и в первой попытке, даже если данные
  уже изменились;
- после 5 неудач доставка помечается `failed` и остаётся в журнале; приёмник
  при этом **не выключается** — иначе после починки события не вернулись бы;
- журнал доставок живёт 30 дней и виден в кабинете.

Требования к адресу: только `https` (исключение — локальная разработка при
`WEBHOOK_ALLOW_HTTP=1`), без логина/пароля в URL, не приватный и не loopback
адрес. Это защита от SSRF; остаточный риск (DNS, указывающий на внутренний
адрес) назван в `app/services/webhooks.py` и закрывается вместе с исходящим
прокси, а не считается решённым.

## Приватность

- ключ и секрет в базе — хеши; в журнале аудита видно создание и отзыв;
- удаление организации (шаг 5.5) удаляет ключи и вебхуки каскадом;
- `contacts.read` не выдаётся по умолчанию: почта — персональные данные.

## Ограничения версии v1

- только чтение: запись требует повторить ограничения ролей и лимитов
  кабинета, это отдельный шаг, когда появится спрос;
- нет фильтров по подразделению и дате изменения;
- нет пагинации вебхуков — их у организации единицы.
