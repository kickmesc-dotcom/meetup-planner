# Кабинет управляющего и доступ (что изменилось)

Срез после MEGAPROMT2, шаг 1: вход в Mini App открыт, управление — по прописанному
доступу, у руководителя появился оперативный экран смены.

## 1. Кто куда попадает

| Кто | Mini App | Вкладка «Команда» | Админка |
| --- | --- | --- | --- |
| Любой человек из Telegram (`initData`) | да | нет | нет |
| Сотрудник (`employees.role=employee`) | да | нет | нет |
| Руководитель (`aup`) | да | своё подразделение | нет |
| Администратор (`admin`) | да | все подразделения | да |
| Прописанный доступ (шестёрка из `WHITELIST_TG_IDS`, владельцы из `ADMIN_TG_IDS`) | да | все подразделения | да |

Раньше `users`-строки создавались только сидом по whitelist, а `/api/*` отвечал
`403 not_in_whitelist` всем остальным. Теперь `initData` проверяется подписью, и
при первом заходе строка создаётся сама (`api/deps.py::_create_user`). Whitelist
остался, но как **пропуск в админку** (`config.staff_tg_id_set`), а не в приложение.

## 2. Роли можно примерить

Админ меняет свою роль на экране профиля (`POST /api/admin/me/role`):

* роль определяет **обзор** (задачи, лента, сводка) — «посмотреть, как бегают
  задачи у сотрудника»;
* доступ в админку остаётся по `is_staff`, поэтому вернуть роль можно той же
  кнопкой;
* ручной выбор фиксируется `employees.role_locked`, и `ensure_employee` больше не
  повышает env-админа обратно на следующем запросе.

## 3. Кабинет «Команда»

`GET /api/admin/dashboard` (`services/hr_ops.py`) отдаёт за текущую смену:

* плитки: начато смен / закрыто / просрочено / открытых проблем;
* «Требует внимания»: просроченные поручения, открытые проблемы, незакрытые к
  вечеру смены (порог — 2 часа до закрытия из рабочих часов);
* подразделения: начали/закрыли, просрочки, проблемы;
* люди: тег подразделения, прогресс чек-листа, просрочки, статус смены;
* последние действия по задачам.

Область видимости считает сервер: `aup` — своё подразделение, `admin` — всё.
Прямой запрос с чужим `department_id` ничего не расширяет.

## 4. Рабочие часы и тихие часы

Настройки (`PUT /api/admin/settings/hr`):

* `work_open` / `work_close` (`HH:MM`, ночная смена поддерживается);
* `notify_only_work_hours` — по умолчанию включено;
* `notify_lead_minutes` / `notify_tail_minutes` — час до открытия и час после
  закрытия;
* мьют: `POST /api/admin/notifications/mute` — 24 ч / 3 дня / 7 дней / 30 дней,
  `hours=0` снимает.

Вне окна или при мьюте Telegram-алерты не отправляются, но уведомление в
приложении создаётся всегда — утренний разбор не теряется (`hr_reminders._deliver`).

## 5. Обучение в онбординге

После подразделения и опыта идёт этап `training`: семь уроков по приложению
(`services/hr_training.py`). Прогресс — `employee_training_steps`,
`GET /api/me/training`, `POST /api/me/training/{code}`; последний урок переводит
`employees.onboarding_state` в `done`. Уроки идемпотентны: повторная отметка не
создаёт дубль.
