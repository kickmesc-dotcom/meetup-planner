# Пересборка бэкенда в Amvera и проверка результата

Дата: **13.11.2026**. Нужна после изменений в `backend/`: в проде сейчас код
`2fbdb5c64eca`, а в `main` уже есть коммиты про редкое продление лиза,
тихие часы сторожа и поле `scheduler.lease` в `/api/meta`.

## Почему «пересборка», а не «перезапуск»

Amvera запускает **собранный образ**. Перезапуск поднимает тот же образ, то есть
старый код: изменения из git в него не попадают. Нужна пересборка из
репозитория — она заново пройдёт `pip install` и `alembic upgrade head` при
старте контейнера.

Текущее состояние на момент написания:

```
amvera  код 2fbdb5c64eca · 429 путей · миграции-код 0075_org_link_keys
        база neon · …neon.tech · миграции-БД 0075_org_link_keys
hf      ✗ нет ответа от /api/meta
```

## Шаги

1. Панель Amvera → проект `meetup-planner` → **Пересобрать** (rebuild), ветка
   `main`, последний коммит.
2. Дождаться статуса `RUNNING` (обычно 2–5 минут). В логах должны быть
   `db.migrate_lock_acquired` и `db.migrate_done`, затем `scheduler.started`.
3. Проверить, что новый код действительно в контейнере (одна команда):

```bash
curl -s https://meetup-planner-youmakemefry.waw0.amvera.tech/api/meta \
  | python -c "import sys,json;d=json.load(sys.stdin);print(d['scheduler'].get('lease'), d['code']['alembic_head'])"
```

**Ожидаемо:** `{'ttl_seconds': 1200, 'renew_seconds': 600} 0075_org_link_keys`.
Если `lease` — `None`, образ всё ещё старый: пересборка не прошла.

4. Быстрая проверка живости:

```bash
curl -s https://meetup-planner-youmakemefry.waw0.amvera.tech/readyz
```

**Ожидаемо:** `{"status":"ok","db":"ok","ms":…}` со временем заметно меньше
прежних ~577 мс (это не следствие пересборки, а состояние базы Neon; после
переезда на Amvera цифра должна упасть в разы).

5. Если что-то не так — `python tools/switch-db.py status`: он покажет код,
   базу и миграции на живом хосте, без правок на нём.

Есть и общая сверка контуров — `backend/.venv/Scripts/python.exe tools/check-hosts.py`.
Она сравнивает локальный код с живым хостом и отдельно печатает строку
`лидер-лиз`. До пересборки вывод такой:

```
лидер-лиз:  поля нет — образ старше правки (продление раз в минуту)
вердикт: роуты совпадают, но образ старше правки /api/meta — пересобрать
ИТОГ: хостов без экономного режима (старый /api/meta): 1 — нужна пересборка
```

Почему недостаточно отпечатка кода: он считается по набору роутов, а правка
была в теле ответа `/api/meta`, поэтому отпечаток не меняется — без строки про
лиз «АКТУАЛЕН» вводило бы в заблуждение. HF Space в этой проверке помечен как
выведенный и его 503 больше не считается расхождением.

## Что это включает

- Продление лидера планировщика раз в 10 минут вместо минуты.
- Сторож планировщика под тихим часом.
- `scheduler.lease` в `/api/meta` — признак, что образ новый.

Экономия квоты Neon начнётся с этого момента; расход CU-часов смотреть в
консоли Neon через сутки (см. `docs/NEON_BUDGET.md` §6).
