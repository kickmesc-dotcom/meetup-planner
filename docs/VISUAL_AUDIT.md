# Визуальный аудит приложения (impeccable, черновик-список)

Аудит сделан вручную по методике скила **impeccable** (установлен локально:
`~/.claude/skills/impeccable`, движок `~/.impeccable/bin/0.1.15`), потому что
автоматический детектор в этой среде недоступен:

- `impeccable context --target src` — выполнен, проект без `PRODUCT.md`;
  скил в этом режиме разрешает узкую ревизию по действующему коду (`SCOPED_EXISTING_ALLOWED`)
  и требует предложить `init` после (не сделан — нужен ответ владельца продукта).
- `impeccable detect --json src` — вернул пустой список (по исходникам правил нет).
- `impeccable detect --viewport 390x844 <URL>` — `Navigation timeout of 30000 ms`
  (браузер скила не достучался до приложения). Поэтому техническая часть собрана
  замерами в нашем браузере: снимки экранов 390×844 и 900×800, вычисленные стили,
  контрасты по WCAG, размеры тач-целей, подсчёт классов и эмодзи по коду.

Ничего из этого списка **не применено**: сначала нужно решение владельца.

## Как читать список

- **P0** — блокирует задачу или нарушает WCAG AA.
- **P1** — заметно мешает и читается как «недоделано».
- **P2** — шум, который снижает качество, но жить не мешает.
- **P3** — полировка.

## P0 — исправить до релиза

1. **Контраст главной кнопки в тёмной теме.** Белый текст на `#5288c1` даёт
   3.72:1. Варианты: тёмный текст на светлой кнопке, либо свой оттенок
   `tg-button` для тёмной темы (`#3b6ea5` даёт ≈4.9:1). Файлы:
   `styles.css` (палитра темы), `tailwind.config.ts` (`tg-button`, `tg-button-text`).
2. **Тач-цели 32px** у переключателей в шапке «Смена»/«Первый день» и у
   иконочных кнопок 32×32 в «Задачах» (📚 🔍 📤). Стандарт — 44×44.
3. **Сырые системные записи в кабинете руководителя** — уже исправлено в коде
   (`hr_ops` + админский журнал), но проверку стоит повторить на живых данных.

## P1 — заметно мешает

4. **Иконки-эмодзи как основной язык интерфейса.** 66 из 84 файлов: 🧑🍳 🍸 📋
   🎓 🛠 🌙. На разных ОС они выглядят по-разному (Windows — цветные, часть
   платформ — чёрно-белые), из-за чего «фирменный» вид теряется. Предложение:
   один набор SVG (12–16 шт.: смена, задачи, события, команда, профиль, проблема,
   обучение, уведомление, передача смены), эмодзи остаются только в игровых
   формулировках.
5. **11px как тело текста.** `text-[11px]` встречается 257 раз, включая описания
   и подписи вторичных действий. Оставить 11px только для мета-строк (время,
   счётчики), остальное — 12–14px.
6. **Смешение радиусов.** `lg` 298 против `xl` 212 и `md` 148 — карточки внутри
   карточек выглядят как «радиусы по настроению». Предложение: один радиус
   карточки (`xl`, 12px), один для внутренних плиток (`lg`, 8px), один для
   пилюль (`full`).
7. **Профиль перегружен.** 15+ блоков, 14 «быстрых переходов» дублируют таб-бар
   и разделы. Предложение: оставить 3 блока (кто я; опыт/обучение; данные) и
   свернуть «быстрые переходы» в один список-ссылку.
8. **Лента: тройная метка тестового сотрудника.** `[BOT]` в имени + бейдж `BOT`
   + плашка («Стажёр») в одной строке. Предложение: плашку ставить один раз и
   только для живых людей, тестовый пул показывать одной пометкой.
9. **Админка — один длинный список из 12+ разделов** без поиска и группировки
   по частоте. Предложение: поиск по разделам + «частые» наверху.
10. **Уведомления/журнал в кабинете руководителя кричали техническими словами**
    (`auto_overdue`, `reminder sent`). Уже уехало в админку с человеческими
    подписями; в кабинете стоит оставить только действия людей (сделано).

## P2 — снижает качество

11. **Копирайт в админке**: «Только для Серж-NEO-уровня админов» — фраза про
    внутреннюю кухню, а не про человека. Переписать через «для управляющих».
12. **Пустые состояния без действия.** «На сегодня всё» + кнопка «События»
    (дублирует таб-бар) и большая пустота. Предложение: пустое состояние ведёт к
    главному действию смены («Начать смену» / «Открыть чек-лист»).
13. **Дублирование смысла в шапках.** «Все предприятие» в пилюле и
    «Всё предприятие.» подзаголовком; «Серж-NEO» в приветствии и рядом в
    плашке. Убрать повтор.
14. **Скроллбары ОС (Windows) в мобильной вёрстке** видны на светлом фоне.
    Предложение: тонкий кастомный скроллбар или скрытие на мобильном.
15. **Значения по умолчанию в «Профиле» для управляющего** («Подразделение не
    выбрано», «Опыт не указан») — выглядит как незаполненный профиль вместо
    администратора. Для staff-ролей блок «Мои данные» показывать иначе.

## P3 — полировка

16. Один акцентный цвет на экран: сейчас и синяя кнопка, и зелёная плашка
    «выполнено», и цветные статусы соревнуются в заголовке.
17. Анимации: `fade-in-soft` есть, но переходы между табами резкие; добавить
    мягкий переход 120–150 мс (с уважением к `prefers-reduced-motion`).
18. Типографика: числовые значения (XP, места) уже `tabular-nums` — распространить
    на счётчики в шапках списков.

## Что сделано хорошо (не трогать)

- Светлая тема по умолчанию и явное сохранение выбора в `localStorage`.
- Статусная палитра (`--status-*-pill`) подобрана с проверкой контраста и не
  зависит от темы.
- `prefers-reduced-motion` уже учитывается в `styles.css`.
- Лента, команда и отчёты считают область видимости на сервере — UI не решает
  за права.

## Рекомендованный порядок работ

1. P0.1 контраст кнопки → P0.2 тач-цели.
2. P1.4 единый набор иконок → P1.5 типографика → P1.6 радиусы (один проход по
   вёрстке, без изменения логики).
3. P1.7 профиль и P1.8 лента (информационная архитектура, без переписывания
   ядра).
4. P1.9 админка (поиск и группировка разделов).
5. P2 и P3 — одним полировочным проходом (`impeccable polish`).
