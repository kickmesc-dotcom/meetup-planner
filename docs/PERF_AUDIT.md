**Статус на 06.11.2026: находка #1 закрыта.** Экраны вкладок переведены

обёрнуты в `Suspense` на своих ранних возвратах. Замер до/после (одна и та
же сборка, один и тот же `vite`):

| --- | --- | --- |

DCL в этих двух замерах **не сравним**: оба раза вкладка была в фоне и не
отрисовывалась, а фоновая вкладка получает меньше процессорного времени. Как
«стало быстрее» это читать нельзя; объективные результаты шага — переданный
объём (278 → 208 КБ) и размер главного чанка (263 → 196 КБ gzip). Для честного
сравнения времени нужен активный экран или Lighthouse на эмуляции 3G.

Проверено: фронт 837 тестов в 104 файлах (все зелёные), `tsc` чисто, Pages
`3c66b107`; прод отдаёт новый бандл (`index-VXmLEaOq.js`) с `br`.
Попутно вылечены два дефекта самого теста мастера настройки: динамический
`import()` в `beforeEach` не укладывался в таймаут хука (отсюда плавающий

**Статус на 06.11.2026: находка #2 закрыта.** Ответы API сжимаются
`GZipMiddleware` (`main.add_compression`, порог 512 байт). Порог не «на глаз»:
`/api/texts` (732 байта подписей) выигрывает, `/healthz` (15 байт) — нет, и
заголовки там дороже экономии. Сжатие стоит самым внутренним middleware,

помечена `Content-Encoding: identity` (`routes_media.media_headers`), потому что
JPEG/PNG уже сжаты, а процессор контейнера 0.5 ГБ нужен галерее, а не
повторному сжатию.

**Статус на 06.11.2026: находка #3 закрыта.** Список поручений собирается
пакетно (`_task_admin_outs`): назначения, имена, фото и legacy-адресаты

Проверено: бэкенд 1911 passed, 11 skipped (+4 теста батча).

**Статус на 06.11.2026: находка #5 закрыта (структурно).** Лента собирает шесть
источников, и каждый запрос — `ORDER BY <время> DESC LIMIT 50`; индексов на эти
колонки не было ни у одного (у `task_events` и `task_photos` есть только
`(task_id, …)`, для ленты бесполезные). Миграция `0072_feed_indexes` добавляет
`(org_id, время)` на `checklist_runs`, `checklist_completions`, `task_events`,
`task_photos`, `task_issues`, `hr_kudos`. `org_id` первым — потому что
тенантский фильтр (`db/tenancy.py`) сам добавляет `WHERE org_id = …` в каждую
ORM-выборку; `DESC` в определении не нужен — btree читается в обе стороны.

**Что не измерено и почему.** `EXPLAIN ANALYZE` на боевой базе с этой машины не
снять: прямого доступа к прод-Postgres нет, а гонять замер через API нельзя —
ручка ленты не показывает план. Поэтому здесь нет цифры ускорения: заявлено
только то, что проверено — SQL миграции (`alembic upgrade --sql`) и совпадение
головы после выкладки. Число строк и время отклика ленты надо снять на живой
базе владельцем или из метрик Amvera, и только тогда писать «стало быстрее».

не битые ключи.

недоступном домене, поэтому «стало быстрее на N мс» здесь не заявляется:
измерен сам факт — один дублирующий запрос к чужому домену исчез.

## Что уже хорошо (чтобы не «оптимизировать» повторно)

- Code splitting админки и Suspense-каркасы на месте; `AdminScreen` — отдельный
  чанк 262 КБ.
- Bootstrap объединяет профиль, участников, HR-профиль, поручения и настройки в
  один запрос, с деградацией до поштучных при отказе.
- Дедупликация запросов — на ключах `react-query`; скелетоны и safe-area закрыты.
- Статика Pages отдаётся `br` с `immutable` — повторные визиты почти бесплатны
  (кэшированный замер: 0 КБ переданного).
- CLS 0 на первом визите: каркасы совпадают по форме с контентом.

## Порядок работ (по замеренному влиянию, а не по нумерации)

1. **Ленивые экраны (P1, #1).** `React.lazy` для экранов, которые не первый
   экран; замер — размер главного чанка до/после и число чанков. Критерий:
   главный чанк меньше заметно, первый экран открывается как раньше.
2. **Сжатие ответов API (P1, #2).** `GZipMiddleware` в FastAPI; замер —
   `content-encoding` и размер ответа ленты. Критерий: заголовок есть, размер
   падает, ошибок нет.
3. **N+1 в поручениях (P2, #3).** Пакетная загрузка назначений и имён на список;
   замер — число SQL-запросов на 20 поручений. Критерий: не растёт с числом
   задач.
4. **Словарь переводов (P2, #4)** и **индексы ленты (P2, #5)** — следующими,
   каждая с миграцией/замером соответственно.
5. `telegram-web-app.js` (P3, #6) — только если первый экран всё ещё ждёт его
   после шагов 1–2.

## Как воспроизвести замеры

```bash
cd frontend
npm run build
ls -S dist/assets/*.js | head -3
for f in dist/assets/index-*.js; do gzip -c "$f" | wc -c; done
curl -s -D - -o /dev/null -H 'Accept-Encoding: gzip, br' \
  https://meetup-planner-youmakemefry.waw0.amvera.tech/api/meta | grep -i content-encoding
```

Первый визит — в чистом профиле браузера через `performance.getEntriesByType`
(`resource`, `navigation`); кэшированный замер для сравнения даёт 0 КБ, поэтому
смешивать их нельзя.
