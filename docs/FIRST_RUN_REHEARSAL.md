# Репетиция первого запуска: как проходить её снова и снова

Документ для разработчика. Отвечает на вопрос «как за десять минут увидеть
первый запуск глазами нового человека и не испортить при этом боевые данные».

Инструмент — `tools/rehearsal.py`. Он работает с **отдельным файлом SQLite**
(`backend/.rehearsal.db`) и подменяет `BOT_TOKEN` пустышкой, поэтому локальный
прогон физически не может отправить сообщение в Telegram или открыть Neon.

## 1. Поднять контур

Терминал 1 — база и API:

```bash
cd meetup-planner-main
python backend/.venv/Scripts/python.exe tools/rehearsal.py fresh

cd backend
DATABASE_URL="sqlite+aiosqlite:///$(pwd)/.rehearsal.db" \
BOT_TOKEN=0:rehearsal-local TG_WEBHOOK_SECRET=rehearsal-local \
MINI_APP_URL=http://localhost:5173 PUBLIC_BASE_URL= \
./.venv/Scripts/python.exe -m uvicorn app.main:app --port 8010
```

Терминал 2 — фронтенд с проксированием API на локальный бэкенд:

```bash
cd meetup-planner-main/frontend
VITE_DEV_API_PROXY=http://127.0.0.1:8010 npm run dev -- --port 5199
```

`fresh` печатает логин и пароль руководителя и код компании. Приложение —
`http://localhost:5199`.

## 2. Команды

| Команда | Что делает |
| --- | --- |
| `fresh` | новая база: владелец + организация, мастер настройки ещё не пройден |
| `new-staff --alias 3` | ещё один «только что нанятый»: аккаунт без организации |
| `rerun <email>` | вернуть человека в начало знакомства |
| `rerun <email> --cold` | ещё и выйти из организации (экран «кто вы в компании») |
| `rerun <email> --org-setup` | заодно сбросить мастер настройки организации |
| `onboarding <email> <state>` | поставить состояние (`new`, `training`, `done`) — чтобы проверить один экран |
| `status` | что в базе: организация, участники, состояния |

Повторный прогон — это `fresh` заново (база пересоздаётся) либо `new-staff` +
`rerun`, если организация уже настроена и хочется проверить только сотрудника.

## 3. Прогон «новичок»

Цель: человек впервые видит приложение, плохо читает по-русски и не знает
слов «чек-лист», «поручение», «эскалация».

1. `fresh`, затем `new-staff --alias 1`.
2. В приложении: выйти, войти как `staff-1@rehearsal.local`.
3. Пройти: экран «кто вы» → поиск организации по коду → знакомство.
4. Отметить про себя на каждом экране: **что мне тут велят сделать** и **что
   будет, если я нажму не то**. Если ответа нет — это дефект экрана, а не
   человека.

Что проверять обязательно:

* на каждом шаге есть кнопка «дальше» и она активна;
* нет экрана, из которого нельзя вернуться;
* нигде не требуется слово, которого человек не знает, без пояснения;
* после входа не появляется «Нет доступа» без объяснения.

## 4. Прогон «руководитель»

Цель: мужчина 40+, не разбирается в CRM, хочет видеть всё и управлять всем.

1. `fresh` (или `rerun manager@rehearsal.local --org-setup`).
2. Войти как `manager@rehearsal.local`.
3. Пройти мастер: предприятие → подразделения → разделы → приватность → готово.
4. Ответить на вопросы: **где моя команда**, **как позвать людей**, **где я
   вижу, кто что делает**, **как назначить чек-лист**.

Проверка результата — в базе (`status`) и в интерфейсе:

* выбранные подразделения и отрасль **сохранились** (не только в сводке мастера);
* после мастера руководитель не попадает в анкету сотрудника «где ты работаешь»;
* в «Команде» есть приглашение, в кабинете — чек-листы и люди;
* сотрудник, приглашённый ссылкой, не упирается в пустой список отделов.

## 5. Что ловит автоматика

Ручной прогон находит формулировки; регрессии закрывают тесты:

* `backend/tests/test_org_setup_route.py` — мастер действительно сохраняет
  отделы, организация не остаётся без подразделения, владелец не попадает во
  второй онбординг;
* `frontend/src/features/hr/OrgSetupScreen.test.tsx` — уходя с шага, мастер
  отправляет ответы **этого** шага;
* `frontend/src/features/admin/AdminScreen.test.tsx` — владельцу организации не
  показываются системные разделы платформы.

Полный прогон перед выкладкой:

```bash
cd meetup-planner-main/backend && ./.venv/Scripts/python.exe -m pytest -q
cd meetup-planner-main/frontend && npx tsc --noEmit && npm test -- --run
```

## 6. Чего этот контур не проверяет

* Telegram `initData`, бот и рассылки — здесь они отключены намеренно;
* Postgres и миграции: схема собирается из моделей (`create_all`), потому что
  `alembic upgrade head` на SQLite падает на `JSONB`;
* реальную доставку писем — транспорт в режиме «лог».

Результаты прогонов и разбор проблем — в `docs/USABILITY_FIRST_RUN.md`.
