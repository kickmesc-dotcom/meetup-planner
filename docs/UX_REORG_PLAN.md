# UX-реорганизация SemiTaskBot

По мастер-промпту `PROMT/11promt-TEACHER.md`. Правило работы: сначала карта и
приоритеты, потом код; после каждого пакета — проверки и деплой. Ничего не
удаляется только ради чистоты: редкая функция уходит с первого плана, но
остаётся доступной.

## 1. Карта (аудит 07.11.2026)

**Зона сотрудника — нижняя полоса, 5 вкладок:** События (`feed`), Задачи
(`tasks`), Смена (`checklist`), График (`shifts`), Профиль (`profile`).

Вне полосы, но доступны из экранов: проблемы (`issues`), пересменки
(`handovers`), стандарты (`standards`), поиск по знаниям (`ask`), материалы
(`materials`), ссылки (`links`), встречи и опросы (`meetings`), старый
календарь (`calendar`).

**Зона управления — 37 разделов в 8 группах:** «Смена и люди» (12), «Команда и
контроль» (3), «Документы и знания» (3), «Опыт и результат» (1),
«Календарь» (3), «Тексты» (1), «Настройки» (7), «Система» (4–6 в зависимости
от прав). Вход в кабинет — из профиля, раздел «Руководителю»; переключатель зон
наверху.

**Что уже сделано до этого плана:** поиск по разделам, группа «Частое»,
сводка внимания (просрочки + проблемы), единая полоса у всех ролей, настройки
вида и языка в отдельном экране, подсказки в пустых состояниях.

## 3. Целевая логика

1. **Кабинет отвечает на вопрос, а не показывает каталог.** Сверху три
   действия по намерению: разобраться с просрочками, дать поручение,
   пригласить человека. Каталог — ниже, для всего остального.
2. **Два уровня раскрытия, один продукт.** «Простой» режим оставляет людей,
   контроль, результат и настройки; остальное — за кнопкой «Показать все
   разделы». «Расширенный» (по умолчанию) показывает всё, как раньше.
   Переключатель — в «Настройках», выбор запоминается локально.
3. **Одинаковые действия выглядят одинаково.** Одна кнопка основного действия
   на экран, один способ вернуться, один способ подтвердить успех.
4. **Текст — человеческий.** Заголовок называет действие, подпись объясняет
   результат, без внутренних терминов («APScheduler», «legacy»).
