## Блокер №1: пересборка бэкенда (Amvera)

Прод-API `https://meetup-planner-youmakemefry.waw0.amvera.tech` работает на
старом образе. Фронт уже задеплоен и деградирует (кнопка повтора), но новые
ручки и миграции не действуют, пока контейнер не пересобран.

Что ждёт пересборки:

| Миграция | Что включает |
| --- | --- |
| 0076 | наставник (`employees.mentor_employee_id`), «Первая неделя» |
| 0077 | расходники: позиции, движения |
| 0078 | счётчики использования фич (`product_events`) |
| 0079 | пересчёт склада (`is_inventory`) и лимит на смену |

Порядок:

1. Пересобрать образ Amvera из `main` (миграции применяются при старте).
2. Проверить `GET /healthz` и `GET /api/meta` — версия/схема должны совпасть с
   `alembic head` = `0079_supply_counts`.
3. Открыть мини-апп, пройти: «Расходники» → «Пересчитать» → «История»
   (строка с меткой «сверка»), «Неделя», «Первая неделя», проблема →
   «Поручение».

Отдельно: `tests/test_db_alembic_head.py::test_live_databases_match_code_head`
красный, пока живая Neon-база на 0075, а код на 0079. Это не регрессия кода —
это расхождение контура; после пересборки/`alembic upgrade head` тест
позеленеет. До тех пор в локальном прогоне он исключается явно.

## Блокер №2: две базы и два хоста

- Один боевой хост (страница + API на одном домене) — нужно доменное решение.
- Одна база: Amvera и Neon должны смотреть в одну БД, иначе «перенос» данных
  между контурами — ручная работа.
- Пока это не сделано, любые «данные за неделю» на проде могут быть неполными:
  часть записей уходит в один контур, часть — в другой.

## Блокер №3: защита ветки

`main` не защищён: CI зелёный, но мёрж можно сделать без проверок.

1. Settings → Branches → Add branch protection rule → `main`.
2. Включить: Require status checks (backend tests, frontend build, e2e),
   Require a pull request before merging, Do not allow bypassing.
3. После включения — прогнать один PR от начала до конца, чтобы убедиться, что
   проверки действительно блокируют.

## Проверки на живой поверхности

Их нельзя закрыть из терминала — нужен человек с устройством.

- **Телефон (Telegram, iOS и Android).** Пройти смену: чек-лист, поручение,
  проблема, склад без сети (авиарежим), возврат сети. Отдельно — офлайн с
  первого визита; в эмуляции Playwright перезагрузка ломает сценарий, поэтому
  вывод «работает» делается только на телефоне.
- **NVDA и VoiceOver.** Экран смены и карточка проблемы: чтение статусов,
  фокус в нижних листах, объявления после действий.
- **Lighthouse** на ленте и кабинете — на реальном устройстве, не в CI.
- **RUM/INP**: открыть 5–10 реальных сессий, посмотреть p75 INP; LCP/CLS уже
  измерены (2,3 с / 0).
- **Usability ×5**: протокол готов (`docs/UX_SKILL_AUDIT.md`), сессий не было.
