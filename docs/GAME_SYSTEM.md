# GHG10 — игровая система: как устроена и как её перелопатить

Документ отвечает на два вопроса: **что где лежит** (чтобы не искать по коду) и
**что править, если захотелось другой баланс** (задание требовало: «чтобы всю
систему левел-апов можно было перелопатить в один промт»).

## 1. Главное правило: все числа — в одном файле

`backend/app/services/game/config.py` — **единственная точка тюнинга**. В нём нет
логики, только данные: сколько опыта за что, сколько нужно на уровень, как
называются и как выглядят ранги, что открывает каждый ранг.

Если появляется новое число (порог, цена, лимит, цвет) — оно идёт туда. Код
(`levels.py`, `xp.py`, `gates.py`, `report.py`) читает только эти структуры.

| Что | Где | Кто использует |
| --- | --- | --- |
| Цена уровня, максимум, престиж | `XP_PER_LEVEL`, `MAX_LEVEL` | `levels.py`, витрины |
| Опыт за события | `XP_RULES` (код, цена, название, лимит) | `xp.award`, `report.xp_rules_text` |
| Ранги (имя, цвет, жирность) | `RANKS` | `levels.rank_for_level`, UI |
| Что открывает ранг | `LEVEL_UNLOCKS` | `flags.required_level`, `gates` |
| Человеческие названия фич | `FEATURE_TITLES` | уведомление о левел-апе, чат |
| Юбилеи ачивок | `ANNIVERSARY_TIERS` | каталог ачивок |
| Пороги-накопители | `THRESHOLDS` | каталог ачивок |
| Донат, мемы, праздники | `DONATION_*`, `MEME_*`, `DEAD_POST_HOURS`, `UNEMPLOYED_WEEKS` | `donations.py`, `memes.py` |

## 2. Карта модулей

```
backend/app/services/game/
  config.py                 — все числа (см. выше)
  levels.py                 — ЧИСТАЯ арифметика: xp → уровень/ранг/престиж/прогресс
  xp.py                     — начисление опыта + окна идемпотентности + дневная история
  achievements_catalog.py   — каталог ачивок (20 базовых + тиры) в КОДЕ, не в БД
  achievements.py           — выдача ачивок, счётчики, чарты, анонсы
  awards.py                 — ФАСАД: единственная точка входа для событий бота
  flags.py                  — рубильник `game.enabled` + гейтинг-предикаты
  gates.py                  — ранговый гейтинг (403 `rank_required:<N>` / текст в чат)
  weekly.py                 — недельные звания («Рупор поколения» / «Read only»)
  holidays.py               — пул праздников (+CRUD), +50 XP всем
  immunity.py               — пожизненные иммунитеты за 9/10 ранги (Э9)
  donations.py              — донат 100 XP имениннику (Э11)
  memes.py                  — телеметрия мем-постов (Э7)
  report.py                 — тексты для чата: своя стата, чарт, правила опыта,
                              список ачивок
backend/app/services/immunity.py   — общие типы причин иммунитета (ДР + ранги)
```

Схема БД (`db/models.py`): `game_profiles` (опыт, «своё» в профиле, непоказанный
левел-ап), `xp_events`/`xp_daily`/`xp_grants` (история, дневные агрегаты, маркеры
окон), `user_achievements`, `achievement_counters`, `game_holidays`,
`game_media_posts` (телеметрия мемов), `chat_activity_daily` (недельная
активность). Миграции — `0018_game`, `0019_game_counters`, `0020_game_levelup`,
`0021_game_media_posts`; применяются контейнером на старте (`alembic upgrade head`).

## 3. Три инварианта, на которых держится система

1. **Рубильник.** `game.enabled` (в `admin_config`) выключает модуль целиком:
   `awards.*` начинается с проверки, `gates` при выключенной игре снимает гейт, а
   игровые job'ы не регистрируются вовсе (см. `scheduler.reload_dynamic_jobs`).
   Выключенная игра = поведение бота «как до GHG10».
2. **Опыт — источник правды.** Уровень, ранг, престиж и иммунитеты **выводятся**
   из `game_profiles.xp` (`levels.py`). Ничего из этого не хранится, поэтому
   правка баланса не требует миграции и не оставляет «застрявших» уровней.
   Единственное хранимое игровое состояние — «непоказанное уведомление о
   левел-апе» (`pending_level_up_from/to`), потому что его из опыта не вывести.
3. **Игра не ломает бота.** Каждая функция фасада обёрнута `_guarded`: исключение
   логируется как `game.award_failed`, транзакция откатывается, вызывающий код
   продолжает работу. Требование к вызову одно: звать после собственного
   `commit` (кроме `awards.message`, которая пишет и коммитит сама).

## 4. Опыт: источники и окна

`XP_RULES` описывает события; `limit` задаёт окно идемпотентности (`day`, `week`,
`year`, `once`, `None`). Ключ окна живёт в `xp_grants` (`xp.idem_key`), поэтому
повтор события молча не начисляет (`AwardResult.awarded = False`), а не падает.

Некоторые события используют `discriminator` — когда в одном окне возможен не
один законный случай: лох дня (лимит `day`, дискриминатор = id ролла), встреча,
праздник (дискриминатор = id праздника), донат (получатель + год).

Так как события накапливаются и в `xp_daily`, в профиле есть «история за сегодня»
(«сообщения ×12 → +12 XP»); в 00-00 она «обнуляется» фильтром по дате, а не
удалением строк.

## 5. Ачивки

Каталог лежит **в коде** (`achievements_catalog.py`) — не в БД. Тир-версии не
пишутся руками: они разворачиваются из `tiers` (юбилеи 10/20/30/50/100), код
тира — `<base>:<tier>`. Типы: `counter` (по данным), `threshold` (по счётчику из
`achievement_counters`), `instant`. Каждая ачивка даёт +50 XP (капстоун — +100) и
анонсируется в чат со ссылкой на мини-апп.

Спец-ранг «Верховный чухан» (капстоун «С почином ×100») приоритетнее ранга за
уровень — это единственное исключение из правила «ранг = уровень».

## 6. Иммунитеты и мем-телеметрия

- **Иммунитеты (Э9).** `immunity.py` берёт порог из `LEVEL_UNLOCKS` и отдаёт
  карту `user_id → причина`; дальше она вливается в ОБЩИЙ механизм иммунитета
  именинника (`services/birthday_immunity.py`): он же решает, оглашать ли
  («мог бы стать X, но …») и рероллить. Режим announce/silent общий — из
  `birthdays.immunity_mode`. Иммунитет не хранится: сняли опыт — снялся иммунитет.
- **Мемы (Э7).** media-хендлер пишет пост в `game_media_posts`; реакция, reply
  или сообщение в течение часа — отклик. Job `game_memes_sweep` (каждые 10 минут)
  закрывает окно («Мемолог» — отклики всех живых) и 12-часовой рубеж
  («Успешный успех», либо «Forever alone» + «Опиум»).
- **Донаты (Э11).** `donations.donate` переводит 100 XP двумя записями в одной
  транзакции (донор теряет, именинник приобретает) и проверяет четыре правила
  задания: не себе, только в день ДР по сохранённой дате, раз в году на
  получателя, хватает своих очков.

## 7. Где система видна человеку

| Поверхность | Что показывает |
| --- | --- |
| Мини-апп, профиль | карточка ранга со шкалой/престижем, уведомление о левел-апе, история дня, «🎨 Кастомизация», экран «🏅 Ачивки и ранги» + «🎉 Праздники» |
| Мини-апп, торт в календаре | 🎁 донат 100 XP имениннику |
| Чат | `/levels`, `/rank`, `/ranks`, `/xp`, `/ach`; анонсы ачивок, левел-апов, праздников, иммунитетов |
| Админка | «🏅 Игровая система» → рубильник, отладочные TG-id, выдача/сброс ачивок, ручной опыт |

## 8. Как перелопатить систему (шпаргалка)

**Поменять баланс** (цена уровня, XP за события, пороги, цвета, названия):
правим только `config.py`. Миграций не нужно — ничего из этого не хранится.

**Добавить источник опыта:**
1. `config.py`: новый `XpRule("code", points, "Название", limit=...)` + константа `EV_*`;
2. `awards.py`: функция события (`@_guarded`, проверка `_enabled`);
3. вызвать её в точке события (после `commit` вызывающего кода);
4. тест: начисление + повтор в том же окне.

**Добавить ачивку:** запись в `_BASE` каталога (`kind`, `points`, при
необходимости `tiers`/`threshold`/`secret`/`needs_telemetry`). Команда `/ach`
и экран ачивок рисуют список из каталога — править их тексты не нужно:
счётчик нужен — константа `COUNTER_*` в `achievements.py` и функция `on_*`,
которую зовёт фасад.

**Добавить ранговую фичу (гейт):**
1. `FEATURE_TITLES["код"] = "Человеческое название"`;
2. `LEVEL_UNLOCKS[ранг] += ("код",)`;
3. в точке действия — `await gates.require_feature(session, user, "код")` (API)
   или `check_feature(...)` + `denial_message` (чат);
4. фронт: `useGameFeatures().can("код")` — закрывать UI до запроса.

**Переставить имунитет на другой ранг** — правим только `LEVEL_UNLOCKS`;
порог и тексты оглашения поедут за ним.

## 9. Тесты и операции

```
cd backend
.venv/Scripts/python.exe -m pytest -q          # весь бэкенд
.venv/Scripts/python.exe -m ruff check app tests
```

Игровые тесты: `test_game_core.py`, `test_game_achievements.py`,
`test_game_surfaces.py`, `test_game_gates.py`, `test_game_immunity.py`,
`test_game_memes.py`, `test_game_donations.py`, `test_game_chat.py`,
`test_game_admin.py`. Стенда с реальной БД в проекте нет — везде фейк-сессии и
подмена фасада; проверяются решения, а не SQL.

**Типовые операции:**
- выключить игру: админка → «🏅 Игровая система» → рубильник (или ключ
  `game.enabled=false` в `admin_config`);
- проверить 9/10 ранг: там же выставить игроку `xp=800` / `900` и прогнать
  рулетку — сработает иммунитет с оглашением;
- отладить фичу с 1 ранга: добавить свой TG-id в «Отладочные TG-id».
