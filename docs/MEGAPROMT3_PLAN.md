# MEGAPROMT3: упрощение интерфейса — аудит и план

Дополнение к `MEGAPROMT2_PLAN.md`. Задача не «перекрасить», а сделать приложение
понятным без инструкции: меньше текста, ясные действия, светлая тема по
умолчанию, рабочая лента и безопасная проверка «глазами сотрудника».

Работаем по приоритетам из ТЗ (P0 → P1), не переписывая работающее ядро и не
удаляя старые модули (`_legacy` остаётся выключенным).

Статус: **P0 и P1 из ТЗ закрыты** (см. `docs/VISUAL_AUDIT.md` — отдельный список
по визуалу, он ещё не применён и ждёт решения владельца).

## 2. Замечания пользователя (раунд 2) — что с ними стало

1. **«Выбрал в ленте Дмитрия, а вижу действия Петра»** — закрыто: сервер сужает
   выдачу по `employee_id`, добавлен регрессионный тест на оба направления
   (сотрудник / руководитель). Отдельно поправлен показ событий создания
   поручения, из-за которых лента выглядела «не той».
2. **«В команде → последние действия какие-то системные процессы»** — закрыто:
   системные строки из кабинета убраны, для них есть админский **журнал** с
   человеческими подписями (🤖 «напомнил(а) о сроке поручения (авто)»).
3. **«В админке нужен блок уведомлений сотрудников»** — сделано: раздел
   «Уведомления сотрудников» (что ушло, что запланировано, кому и когда),
   выборочное удаление, отправка личного сообщения, перенос напоминания вперёд
   и выключение с возвратом одной кнопкой (правило на задачу, срок поручения
   при этом не меняется).
4. **«Глобальный переключатель: замьютить всё / замьютить на период / отменить
   (двойное подтверждение)»** — сделано: два подтверждения, сроки 24 ч / 3 дня /
   7 дней / 30 дней и «Снять мьют». Мьют глушит доставку в Telegram; в приложении
   уведомления копятся (это написано прямо под кнопками).
5. **«Редактируемый пул сотрудников»** — сделано: переименование, должность,
   плашка, «Обнулить прогресс», «Зачесть проваленное поручение» (в журнале).
6. **«Отдельная кнопка „уволить сотрудника“ с двойным подтверждением»** —
   сделано: доступ закрывается сразу, затем выбор — корзина на 30 дней с
   восстановлением, либо удаление сразу и бесповоротно (второе подтверждение в
   каждом варианте).
7. **«„Сбросить текущую работу“ ответило „сбрасывать уже нечего“»** — код был
   прав (в боевых данных открытого не было), но объяснение отсутствовало. Теперь
   предпросмотр называет цифрами, сколько открытого в тестовом пуле `[BOT]`, и
   напоминает, что его сносит отдельная кнопка.
8. **«Луна переключает тему, но в задачах переводит в передачу смены»** —
   исправлено: луна осталась только у переключателя темы; передача смены —
   📤.
9. **Визуальный аудит по скилу impeccable** — сделан вручную (движок и правила
   скила найдены и прочитаны, автодетектор в этой среде не запустился): список

   [`VISUAL_AUDIT.md`](VISUAL_AUDIT.md). **Ничего не применено** — ждёт решения.

## 3. Осталось (по-прежнему открыто)

- **Визуал**: список из `VISUAL_AUDIT.md` (P0 — контраст кнопки в тёмной теме
  3.72:1 и тач-цели 32px; дальше — иконки, типографика, радиусы, профиль, лента).
- **Смена на следующую смену вперёд**: выбор режима обучения сделан, но
  «расписание режима по дням» (какой день — обучение, какой — обычный) не
  заводили: нужен контент от администратора.
- **Интеграции** (график, iiko) ждут подтверждённого контракта.
- **Корзина**: восстанавливает профиль и доступ, но не «отменяет» удалённое
  сообщение в живом чате (его уже нет в Telegram). Это ограничение платформы.

## 4. Ограничения и зависимости

- Увольнение удаляет HR-данные (поручения, смены, проблемы, обучение,
  уведомления по задачам), но **не** строку `users` и не историю календаря: она
  общая с наследным контуром. Профиль-надгробие остаётся, чтобы человек не
  завёлся заново.
- Автоудаление корзины работает внутри HR-тика планировщика (`run_hr_tick`),
  то есть требует, чтобы планировщик был жив (он и так нужен для напоминаний).
- Права: руководитель подразделения правит только своих и не может уволить
  администратора; увольнение — только админская роль.
- Порядок полей и тексты — по DESIGN_SYSTEM; свои палитры не вводим.

## 5. Как проверяем

- `pytest` (1293 теста) + живые Postgres-прогоны `tools/hr-pg-test.py`
  (`test_hr_flow_pg`, `test_simulation_pg`, `test_hr_reset_pg` — 7 тестов,
  включая сценарий админских операций: журнал → уведомления →
  перенос/выключение напоминания → увольнение/восстановление/удаление).
  Миграции `0040`–`0042` накатаны на боевую Neon (head совпадает с кодом).
- `tsc --noEmit`, `vitest run` (148 тестов), `ruff` по изменённым файлам.
- Тема: новый пользователь получает светлую, тёмная переживает перезапуск.
- Лента: фильтр по человеку проверен на живом Postgres в обе стороны.
- Уведомления: запланированное напоминание видно заранее; мьют — с двойным
  подтверждением; отправленное убирается по одному.
