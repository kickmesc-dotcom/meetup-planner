# MEGAPROMT3: упрощение интерфейса — аудит и план

Дополнение к `MEGAPROMT2_PLAN.md`. Задача не «перекрасить», а сделать приложение
понятным без инструкции: меньше текста, ясные действия, светлая тема по
умолчанию, рабочая лента и безопасная имитация сотрудника.

Работаем по приоритетам из ТЗ (P0 → P1), не переписывая работающее ядро и не
удаляя старые модули (`_legacy` остаётся выключенным).

## P0 — ближайшие шаги

1. **Онбординг как первый экран.** Стартовый экран «Привет! Давай освоимся»,
   предзаполнение из Telegram/профиля, три коротких шага (кто ты →
   подразделение → опыт), затем сразу «Начать смену». Никаких стен текста.
2. **Личная панель сотрудника.** Первый экран отвечает «что мне нужно сделать»:
   чек-лист смены, задачи, проблемы; пустое состояние «На сегодня всё».
3. **Тексты и иерархия.** Пройти по экранам и сократить описания до одной
   строки, оставить одно главное действие на экран (начать со «Смены», «Задач»,
   «Команды», профиля).
4. **Поиск по сотрудникам.** В списках выбора исполнителя — поиск по имени и
   должности; фильтр по подразделению уже есть.

## P1 — после P0

5. **Уровни обучения.** Сейчас уроки плоские. Нужны уровни «Знакомство →
   Основные задачи → Самостоятельная работа» с сохранением прогресса; контент
   задаёт администратор.
6. **Режим имитации сотрудника.** Отдельный сеанс проверки для админа:
   - выбор любого сотрудника (включая новичка с непройденным онбордингом);
   - постоянный индикатор «Режим проверки · Имя · Отдел» с выходом;
   - **изоляция данных**: каждая тестовая запись помечается `session_id`;
     выход удаляет только эти записи, настоящие задачи сотрудника не трогаются;
   - очистка идемпотентна, ошибка очистки не считается успехом;
   - аудит-запись о старте/финише сеанса.
7. **Полировка ленты.** Группировка по дням, явные подписи действий, отказ от
   «карточки на каждую строку».

## Ограничения и зависимости

- **Имитация требует миграции.** В `tasks`, `checklist_runs`, `app_notifications`,
   `task_events` и ленте нужен признак сеанса (`simulation_session_id`).
   Без него очистка «по имени и времени» запрещена ТЗ — это небезопасно.
- **Уровни обучения** требуют контента от администратора; структуру можно
  завести, но наполнять её выдуманными уроками нельзя.
- **Тексты** меняем постепенно: каждый экран проверяется на мобильном, а не
  переписывается вслепую.
- Интеграции (график, iiko) по-прежнему ждут подтверждённого контракта.

## Как проверяем

- `pytest`, `tsc -b`, `vitest run`, `ruff` — на каждый значимый шаг.
- Тема: новый пользователь получает светлую; тёмная сохраняется после
  перезапуска (юнит-тесты `store/theme.test.ts`).
- Лента: отдел показывает всех людей отдела; сотрудник по-прежнему видит только
  себя (серверные тесты `test_hr_flow.py`).
- Кодировка: имена владельцев чистые в «Команде» и фильтре ленты (проверено на
  боевой базе).
- Имитация: изоляция и очистка — только на живом Postgres, с двумя аккаунтами.
