# Как упаковать бота для чужих чатов: типажи и LLM

> Статус: **план** (не реализовано). Дата: 2026-09-30.
> Цель — превратить «наш бот для нашего чата» в продукт, который владелец другого
> чата может поставить одной командой и выбрать ему характер из готовых типажей.

## 0. Главный принцип: движок отдельно, содержание отдельно

Сейчас логика и «голос» бота перемешаны: движок живёт в сервисах, а тексты — частью
в БД (редактируемые пулы), частью прямо в коде (жёсткие строки в `services/*.py`).
Чтобы продавать бота другим чатам, надо провести границу:

```
          ┌─────────────────────────────┐
движок →  │ механизмы: роллы, XP, кален- │   не зависит от чата и типажа
          │ дарь, события, детект слов   │
          └──────────────┬──────────────┘
                         │  «что сказать» (речевой акт + контекст)
          ┌──────────────▼──────────────┐
контент → │ voice pack: шаблоны типажа  │   выбирается при установке
          └──────────────┬──────────────┘
                         │
          ┌──────────────▼──────────────┐
опционально│ LLM-провайдер (локальный/API)│  придумывает реплику под типаж
          └─────────────────────────────┘
```

Типаж («грозный зек», «девочка-подружка», «офисный», «геймер-бадди», «жёсткий
подъёбщик») — это **voice pack**, а не ветка в коде. Движок не должен знать, какой
типаж включён; он лишь формулирует «нужно объявить лоха, повод такой-то».

## 1. Инвентаризация: где вообще живёт голос бота

Все речевые точки (их нужно покрыть паками). Разделены на две категории:

**A. Уже вынесены в редактируемые пулы** (`admin_config`, ключ → JSON-список;
экспорт/импорт — `services/phrase_snapshot.py`):

| Пул | Что озвучивает | Сервис |
|---|---|---|
| `loser_reasons` | причина «лоха дня» | `services/loser.py` |
| `chukhan_reasons` | причина чухана | `services/chukhan.py` |
| `advice` | «совет от бота» | `services/advice.py` |
| `media_single` / `media_collection` / `media_emoji` | подписи к мем-постам | `services/game/memes.py` |
| `reply_phrases` | короткие реакции на reply/mention | `bot/handlers/*` |
| `worm_master_*` (prefix/suffix/agrees/nag/punish/announce) | режим «червь-господин» | `services/worm_master.py` |

**B. Зашиты в коде** — их и надо вытащить в паки (это основная работа):

- `services/zaebal.py` — реплики заебала;
- `services/birthdays.py` — поздравления;
- `services/dead_chat.py` — «мёртвый чат»;
- `services/game/events.py` — случайные события («признайся», «сначала напиши я»);
- `services/game/memorial.py` — «поминальные» сообщения и «⚠️ ОН ЗДЕСЬ»;
- `services/game/awards.py` + `journal.py` — анонсы ачивок/левел-апов/сводки;
- `services/meeting_feedback.py`, `birthday_immunity.py` — опросы и оглашения.

Речевой акт = стабильный ключ (`loser.announce`, `event.prompt`, `memorial.return`,
`levelup`, `award.unlock`, …). Пак даёт шаблоны на каждый акт.

## 2. Voice pack: формат

Пак — папка (или один YAML/JSON), которая кладётся рядом с кодом или встраивается
в образ:

```
voices/
  hardened-inmate/            # «грозный зек»
    meta.yaml                 # название, описание, язык, версия, теги
    acts.yaml                 # речевые акты → шаблоны с плейсхолдерами
    slots.yaml                # словари для слотов (клички, угрозы, отмазки)
  girlfriend/                 # «девочка-подружка»
  office/                     # «серьёзный офисный тон»
  gamer-buddy/                # «геймер-бадди»
  hard-roaster/               # «жёсткий подъёбщик» (наш текущий)
```

`acts.yaml` (эскиз):

```yaml
loser.announce:
  - "👑 {loser} — {reason}"          # жёсткий подъёбщик: сухо и по делу
  - "Ну всё, {loser}, ты сегодня {reason}"
event.prompt: "🙊 Признайся в чём угодно одним сообщением — +{xp} XP. {deadline}"
memorial.going_silent: "Уже {days} дней от {name} ничего. Мы почти привыкли."
memorial.returned: "⚠️ {name} ОН ЗДЕСЬ. Сервер подтверждает личность."
levelup: "🎉 {name} взял {level} уровень ({rank})"
```

Требования к шаблонам: HTML-совместимы с Telegram, плейсхолдеры типизированы
(`{loser}`, `{days}`, `{xp}`, `{rank}`), в шаблон нельзя вставить произвольный
пользовательский текст без экранирования (иначе XSS/поломка разметки). Валидатор
пака (`voices/validate.py`) проверяет: все обязательные акты есть, плейсхолдеры
известны, есть хотя бы один шаблон на акт, размер в пределах лимита TG (4096).

**Важно про имена.** Сейчас в коде/пулах встречаются имена конкретных людей чата
(«Серж-NEO», «Руслан», слова-контрабанда на участников). Это должно уехать в
конфиг инсталляции (см. §4), а не в пак: пак описывает *характер*, конфиг — *состав
чата*.

## 3. Типажи: набор актов, а не только тон

Типаж — это не только формулировки, но и **дефолтные настройки поведения**, чтобы
владелец не тюнил всё руками:

| Типаж | Тон | Дефолты, отличающие его |
|---|---|---|
| жёсткий подъёбщик | сарказм, коротко | мат-лимит, «лох дня» включён, реплаи агрессивны |
| грозный зек | угрозы, лагерная романтика | «червь-господин» включён, «заебало» доступно |
| девочка-подружка | эмодзи, мягко, забота | ачивки хвалят, нет лоха или мягкий, поминания тёплые |
| серьёзный офисный | нейтрально, без эмодзи | авто-лох выкл., события выкл., отчёты сухие |
| геймер-бадди | XP/ранги/мемы | геймификация на максимум, сводка включена |

То есть `voice pack` = тексты + `defaults.yaml` с настройками фич (перекрываются
конфигом инсталляции и админкой).

## 4. Установка в чужой чат: одна команда

Целевой UX:

```bash
docker run -e BOT_TOKEN=... -e GROUP_CHAT_ID=... -e ADMIN_TG_IDS=... \
           -e VOICE_PACK=hardened-inmate -e DATABASE_URL=...  ghcr.io/.../meetup-bot
```

Что нужно, чтобы это заработало:

1. **Никакого хардкода нашего чата.** Вынести из кода: `group_chat_id`,
   `admin_tg_ids`, имена участников, ID слова-контрабанды, список «владельцев»
   пулов. Часть уже читается из env (`app/config.py`), но тексты/слова — нет.
2. **Онбординг-визард.** При первом старте без настроек бот в личке админа
   спрашивает: тип пак (`VOICE_PACK`), порог «мёртвого чата», включать ли игру.
   Ответы пишутся в `admin_config` — отдельная таблица не нужна.
3. **Миграции автоматом.** `alembic upgrade head` на старте (уже есть механика),
   плюс «первичное засевание» пулов из выбранного пака, если пулы пусты.
4. **Импорт пака.** `phrase_snapshot.py` уже умеет экспорт/импорт пулов — пак
   можно наложить этим же механизмом (`mode=merge`), но добавив «акты, зашитые в
   код» после их выноса в пулы.
5. **Образ.** Сейчас Dockerfile один (`meetup-planner-backend/Dockerfile`); нужен
   публикабельный образ без наших секретов и с `voices/` внутри (или томом).

## 5. Куда подтянуть LLM

**Ключевая мысль:** LLM не должна быть источником истины — бот обязан работать и
без неё. LLM — это «улучшатель реплики», а не движок. Поэтому:

- если LLM недоступна/таймаут/ошибка → молча падаем на шаблон пака (никогда не
  молчим и не тормозим очередь сообщений);
- LLM вызывается только на **речевых актах** (см. §1) и никогда не решает XP,
  роллы, модерацию — это детерминированный код;
- контекст в промпт — минимальный (типаж, акт, 1–2 факта: имя, причина, XP), без
  выгрузки истории чата целиком (иначе приватность чужих чатов и цена).

**Точка подключения.** Новый интерфейс поверх паков:

```python
# services/voice/engine.py (эскиз)
class VoiceEngine:
    async def say(self, act: str, ctx: Mapping[str, Any]) -> str:
        """Вернуть готовый HTML-текст для акта: LLM → шаблон пака (fallback)."""
```

Все места, где сегодня `random.choice(pool)` или f-строка, зовут `say(act, ctx)`.
Это одна воронка — её и закрываем кэшем и лимитами.

**Провайдер.** Абстракция `services/voice/providers/`:

- `provider=ollama` → локальный сервер (Ollama/vLLM) c Qwen2.5-Instruct;
  для 12 GB VRAM реалистичен Qwen2.5-14B-Instruct в 4-bit (GGUF) либо 7B в fp16;
  при 32 GB RAM — держать модель резидентной и не перегружать контейнер;
- `provider=deepseek` → платный API (тот же OpenAI-совместимый chat/completions),
  ключ в `DEEPSEEK_API_KEY`; переключение — переменной окружения, без правок кода;
- `provider=off` → только шаблоны (дефолт для чужих чатов без своего железа).

Конфиг (env): `LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`,
`LLM_TIMEOUT_SEC`, `LLM_MAX_CALLS_PER_HOUR`, `LLM_TEMPERATURE`.

**Стоимость и безопасность.** Обязательны: кэш по (акт, тип, ключевые факты) с
TTL; суточный/часовой лимит вызовов (`LLM_MAX_CALLS_PER_HOUR`); блэклист-фильтр
после генерации (мат, персданные, ссылки) с фолбэком на шаблон; таймаут и «circuit
breaker» (после N подряд ошибок провайдер выключается до конца часа). Логировать
`voice.llm_used` / `voice.llm_fallback` — чтобы видеть, что реально дошло.

**Практический порядок для нашего железа (32 GB RAM, 12 GB VRAM):** начать с
`ollama` + Qwen2.5-14B-Instruct (4-bit) как генератора *черновиков фраз*, которые
админ просматривает и закрепляет в пул (нынешний `SOURCE_AI` уже для этого есть) —
то есть LLM-оффлайн, без рантайма. Рантайм-генерация — второй этап, после того как
паки дадут ей жёсткие рамки. Переход на DeepSeek API — смена `LLM_PROVIDER`.

## 6. Этапы (с критериями приёмки)

1. **Паки-тексты (без LLM).** Вынести жёсткие строки из категории B в пулы/акты;
   завести `voices/hard-roaster/acts.yaml` = текущее поведение (регрессия: текст
   бота после этого не меняется).
2. **VoiceEngine + валидатор паков.** `say(act, ctx)` с фолбэком; `validate.py`;
   тест: каждый акт из реестра есть в паке, плейсхолдеры совпадают.
3. **Ещё 3–4 пака** (зек, подружка, офис, геймер) + `defaults.yaml`; тест — бот
   поднимается на каждом паке и отвечает на все акты.
4. **Мультитенант-установка.** env → конфиг, вынос имён/слов участников, визард
   онбординга, публикабельный образ, README «поставить за 10 минут».
5. **LLM-провайдеры (оффлайн).** `ollama` + Qwen для генерации черновиков в пул.
6. **LLM в рантайме.** Кэш, лимиты, фильтр, circuit breaker, переключение на
   DeepSeek API; наблюдаемость.

## 7. Открытые вопросы (нужны решения)

- Лицензирование/монетизация: открытый код + платные паки или всё открыто?
- Приватность чужих чатов при рантайм-LLM: согласие владельца чата, объём контекста.
- Поставка: Docker-образ (как HF Space сейчас) vs. отдельный SaaS с одним ботом на
  чат (тогда нужна мультитенантная БД, сегодня — одна Neon на обоих хостах).
- Локализация: паки только ru или с самого начала с языковым тегом в `meta.yaml`.
