## Проверка точки отката (настоящая, а не «файлы на месте»)

```bash
python tools/db-rehearsal.py info                      # какие базы есть, какая боевая
python tools/db-rehearsal.py rehearse backups/<штамп>   # пустая база → дамп → сверка
```

`rehearse` создаёт **отдельную пустую** базу (`ghg_rehearsal_<штамп>`) на резервном
инстансе (если в `leltokens2.txt` только один DSN — на том же, с предупреждением),
прогоняет `alembic upgrade head`, заливает дамп и сравнивает слепки.

Важная деталь методики: восстановленное сравнивается **с дампом**, а не с боевой
базой. Боевая база живёт и пишется — сравнение с ней ловит не дефект
восстановления, а свежие записи. Дрейф боевой базы с момента дампа печатается
отдельным блоком и не влияет на вердикт.

`restore` в `tools/backup-db.py` — это upsert, а не `insert … on conflict do
nothing`: миграции засевают часть таблиц (например, дефолтный Новый год в
`game_holidays`), и `do nothing` молча оставляла бы засеянную строку вместо
строки из дампа. Плюс после заливки пересчитываются последовательности
(`setval` по `max(id)`), иначе следующий INSERT в приложении падал бы с
duplicate key на восстановленной базе. Отключить удаление «лишних» строк (тех,
которых нет в дампе): `--no-prune`.

## Транзиентные сбои фоновых job'ов

Фоновый прогон больше не падает целиком из-за секундного сетевого блипа. Тюнинг

## GHG11 — единая модель доставки бота (off / chat / app / both) + правки

### Ядро: `services/game/delivery.py`

- НОВЫЙ модуль. Каждая функция бота описывается одним из ЧЕТЫРЁХ состояний:
  `off` (выкл) · `chat` (только чат) · `app` (только мини-апп) · `both` (чат+апп).
- Реестр `FEATURES` (19 фич) + `FEATURE_BY_KEY`. Мастер-модули: `general`
  (все фичи, КРОМЕ ачивок) и `achievements` (ачивки — строго отдельно).
- Ключи в `admin_config`: `delivery.master.<module>` и
  `delivery.feature.<key>`. Эффективный режим = оверрайд фичи → мастер модуля →
  дефолт `chat`.
- `get_master_status()` выводит мастер ИЗ текущих фич: разъехались → `custom`.
  `set_master_mode()` переводит ВСЕ фичи модуля; `set_feature_mode()` — одну.

### Проводка

- `journal.announce()` маршрутизирует по режиму фичи для journal-видов
  (achievements/holidays/events/contraband/memorial): `off` — дроп, `app` —
  строка только в ленте, `both` — чат + лента. Legacy-режим
  `chat.output_mode` остаётся в силе поверх новой модели (обратная совместимость).
- `journal.send_now(..., feature=)` — чат-часть фичи молчит в `off`/`app`.
- `achievements.grant()` не выдаёт ничего при `off`; `announce_granted()` при
  `app` пишет только в ленту.

### API

- `GET /admin/delivery` — мастера + режимы всех фич.
- `PUT /admin/delivery` — правка мастеров / одной фичи / пачки.
- `POST /admin/delivery/apply-all` — одним кликом перевести ВСЁ в один режим.

### Ачивки (п.5 оператора)

- Лох (`chin_up`) и чухан (`first_worm`): тиры теперь ровно `(10,)` — «впервые»
  + единственный юбилей ×10; прочие ×20/×30/×50/×100 убраны.
- `ACHIEVEMENTS_ERA_START` сдвинут на `2026-10-04` — учёт накопителей с текущей
  даты (старая стата лоха/чухана не считается; выданные ачивки не отзываются).

### Автолох (п.3 оператора)

- `admin_config`: `autoloser.days` (дни недели, пусто→все), `autoloser.mode`
  (`fixed`/`random`/`interval`), `autoloser.fixed_hour/minute` (18:00),
  `autoloser.interval_slot` (`day`/`night`).
- Раздельные интервалы `intervals.day_*` / `intervals.night_*` (07:00–23:00 /
  23:00–07:00) — общая величина для других фич.
- Scheduler: `_build_autoloser_trigger` умеет три режима + дни недели; job
  пропускает дни вне выбранных и глушится при режиме `off`.
- `/admin/autoloser` PUT стал частичным; пустой набор дней → фича ВЫКЛ.

### Отладка игрока (п.12)

- `POST /admin/game/xp/add` — прибавить/отнять опыт.
